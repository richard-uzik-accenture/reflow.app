1. Give the duel commit its own module

Strong in-process

src/lib/swipe.ts · src/components/CompareDuel.tsx (DuelCard.commit)

Problem

A pure function was extracted for testability — decideSwipe — but it only answers "which way." The actual duel behavior (fling distance, velocity-scaled duration, haptic pulse, snap-back spring, when onResolved fires) lives inside DuelCard.commit, untested, un-testable through any interface but the rendered component. swipe.ts is the only file in src/lib with no sibling *.test.ts — because the module that would need testing isn't the one that got extracted.

Solution

Deepen swipe.ts into a duel-resolution module: given offset, velocity, and threshold, it returns a plan (direction, fling duration, distance, whether a haptic fires) rather than just a direction. DuelCard becomes an adapter that plays the plan through framer-motion's animate() and calls navigator.vibrate — no decisions left in the component, only playback.

Before — logic split across the seam
After — one deep module, one adapter

Wins

  • Locality: fling/haptic bugs concentrate in one module
  • Interface is the test surface — commit logic testable at last
  • DuelCard shrinks to pure playback, no decisions
  • Leverage: one resolver, reusable if swipe UX appears elsewhere

2. Collapse Today's duplicated failed-row handlers

Worth exploring in-process

src/pages/Today.tsx (handleComplete, handleDrop)

Problem

handleComplete and handleDrop are the same four lines twice: call the mutator, and on failure set failedRowId then clear it after a fixed 2000ms via a guarded timeout. Today.tsx's interface (its local handler functions) is doing work that belongs to the task list's failure-feedback behavior, not page wiring. A third row action (e.g. a future "snooze") would copy-paste a third copy.

Solution

Wrap in one helper — withFailedRowFlash(id, mutate) — that runs any row-scoped mutator and manages the flash timer. Today.tsx calls it twice with different mutators instead of hand-rolling the flash logic twice.

Before — two copies
handleComplete(id)
await completeTask(id)
if !ok → setFailedRowId
setTimeout 2000ms → clear
handleDrop(id)
await dropTask(id)
if !ok → setFailedRowId
setTimeout 2000ms → clear
After — one helper, two callers
withFailedRowFlash(id, mutate)
owns the flash timer once
onComplete = (id) => withFailedRowFlash(id, completeTask)
onDrop = (id) => withFailedRowFlash(id, dropTask)

Wins

  • Locality: flash-timer bug fixed once, not twice
  • Today.tsx interface shrinks by one duplicated shape
  • Leverage: next row action reuses the helper for free

3. Deepen useTasks around one optimistic-mutation primitive

Worth exploring in-process

src/hooks/useTasks.ts (completeTask, editTask, dropTask, keepLeftover, commitReorder)

Problem

Five of useTasks's nine exported functions repeat the same shape: snapshot previous = tasks, apply an optimistic setTasks, await the Supabase call, and on failure restore previous plus set a describeFailure error. The interface (9 async functions) is nearly as wide as summing up the implementation, because the implementation is the same 6-line pattern repeated with a different mutator and a different failure string. Mass diagram below makes it concrete.

Solution

Extract a single internal optimisticMutate(optimisticNext, apiCall, failureLabel) that owns the snapshot/apply/rollback/error dance. completeTask, dropTask, editTask, keepLeftover become one-line callers. This is an internal seam only — useTasks's external interface (the 9 functions Today.tsx calls) stays exactly the same, so nothing downstream changes.

Note: commitReorder's rollback restores a ref snapshot taken at drag-start, not the pre-call tasks — it doesn't fit the primitive as cleanly as the other four. Worth confirming during design whether it joins the primitive or stays a documented exception.

Wins

  • Locality: rollback bugs fixed in one place, not four-to-five
  • Interface shrinks relative to implementation it now hides
  • External seam (useTasks's 9 functions) unchanged — no ripple
  • New optimistic mutations become one-liners
